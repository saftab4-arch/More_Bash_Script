# EC2 SSH Log Analyzer (Bash)

A menu-driven Bash script that analyzes real SSH authentication logs on an Amazon EC2 Linux instance.

This project was built to practice Linux administration, Bash scripting, log analysis, and troubleshooting using actual SSH logs generated by a live EC2 server.

---

# Project Overview

Instead of using sample log files, this project collects real SSH authentication events from the systemd journal and allows users to interactively analyze them through a menu-driven Bash application.

The script can:

- Display failed SSH login attempts
- Display successful SSH logins
- Count failed login attempts
- Display recent SSH security events
- Exit the application gracefully

# Workflow

## Step 1

Collect SSH logs from systemd:

```bash
journalctl -u sshd --no-pager > /tmp/ssh_logs.txt
```

---

## Step 2

Store the log file location:

```bash
LOG_FILE="/tmp/ssh_logs.txt"
```

---

## Step 3

Display an interactive menu:

```text
1. Show Failed SSH Logins
2. Show Successful SSH Logins
3. Count Failed SSH Logins
4. Show Last 10 Security Events
5. Exit
```

---

## Step 4

Use grep and tail to analyze SSH activity.

# Full Script

```bash
#!/bin/bash

# Export SSH logs from systemd journal
journalctl -u sshd --no-pager > /tmp/ssh_logs.txt

# Log file path
LOG_FILE="/tmp/ssh_logs.txt"

while true
do

echo
echo "===== EC2 SECURITY LOG ANALYZER ====="

echo "1. Show Failed SSH Logins"
echo "2. Show Successful SSH Logins"
echo "3. Count Failed SSH Logins"
echo "4. Show Last 10 Security Events"
echo "5. Exit"

read -p "Choose an option: " choice

case $choice in

1)
    grep "Failed" $LOG_FILE
    ;;

2)
    grep "Accepted" $LOG_FILE
    ;;

3)
    echo "Total Failed Logins: $(grep -c "Failed" $LOG_FILE)"
    ;;

4)
    tail -10 $LOG_FILE
    ;;

5)
    echo "Exiting..."
    break
    ;;

*)
    echo "Invalid Option"
    ;;

esac

done
```

# Command Breakdown

## journalctl

```bash
journalctl -u sshd --no-pager > /tmp/ssh_logs.txt
```

Purpose:

Exports SSH service logs from the systemd journal into a temporary file.

| Component | Description |
|------------|------------|
| journalctl | View systemd journal logs |
| -u sshd | Filter logs for SSH service |
| --no-pager | Print output directly |
| > | Redirect output |
| /tmp/ssh_logs.txt | Temporary log file |

---

# Troubleshooting

## Issue #1 - Missing Log File

Original script referenced:

```bash
/var/log/secure
```

Error:

```text
grep: /var/log/secure: No such file or directory
```

### Root Cause

Modern Linux distributions such as Amazon Linux 2023 store authentication events in the systemd journal instead of traditional log files.

### Resolution

Replaced:

```bash
/var/log/secure
```

with:

```bash
journalctl -u sshd --no-pager > /tmp/ssh_logs.txt
```

---

## Issue #2 - Permission Denied While Saving Script

Error:

```text
Permission denied
```

### Root Cause

The script was created in a directory owned by root.

### Resolution

Used:

```bash
sudo nano log-analyzer.sh
```

and:

```bash
sudo chmod +x log-analyzer.sh
```

to edit and execute the script.

---

## Issue #3 - Script Count Returned Zero

The count option initially searched for a different pattern than the display option.

### Resolution

Standardized all failed-login searches using:

```bash
grep "Failed"
```

and:

```bash
grep -c "Failed"
```
